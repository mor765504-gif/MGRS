# MGRS · 一起讨论 Agent 该怎么替人做事

我做秘秘，最早是想有人帮我理一理多到排不过来的日程。后来让它查资料、整理文档，也让几个 Agent 分头做事，才碰到一个问题：交给助手的事多了，它对我越熟，我究竟希望它自己决定到哪一步？

比如我说「帮我腾出周五下午」。它知道我有两场会，可以先把能挪的时间挑出来。可其中一场约了别人，它能直接替我改吗？如果我平时一直让它自己排日程，这次还要不要问？同一句话，放在我一个人的日历里，和放在三个人共同的约定里，分量很不一样。

**MGRS（Mimi Governed Runtime Standard）是从秘秘这些实际问题里长出来的一套 Agent 治理框架。** 我的出发点是，能交给助手的方法就让它自己选，人仍然能改主意、决定哪些资料可以用。工作分给几个 Agent 以后，新要求也该跟着事情走，用的人不用挨个重新交代。[框架正文](MGRS.md)

我想把这个框架拿出来共创，因为我自己用着顺手的分寸，换个人、换一个团队，未必还合适。你愿意让助手看完下周的邀请、把冲突标出来，也许很不愿意它替你回一封婉拒邮件。你也可能早就把这类决定交给了自己的助手。两种用法都值得讲，尤其是**什么情况下你会改变主意**。可以带一个这样的例子来，也可以直接改草案里你觉得说得不对的那句话。[参与共创](CONTRIBUTING.md)
