## 第十三条 · 真实度量、持续巡检与晋级门禁

### 13.1 沿用户的完整任务评价可靠性

用户把一份报告交给三个 Worker 后，需要催几次、搬运几次材料，最后拿到哪一版合格报告，都属于运行质量。每份评估应写明样本与分母、代码和模型版本、配置、观测时段、失败实例及其影响范围。同一轮任务至少沿相关环节核对以下证据：

- **任务与交接。** 分别统计已接任务、有结果的任务、通过具名验收的产物与实际交付。按原任务和尝试跟踪结果到达授权接收者、进入最终请求、观察到响应、形成合格下游产物各环节的数量、耗时及遗漏。单列重复执行、未决效果与冷恢复后丢失的任务。
- **上下文与边界。** 记录必需约束进入最终请求的覆盖率、相关记忆召回率（如 Recall@K）、无关注入率，以及已撤回、过期或跨身份信息进入请求的次数。
- **Persona 与 Skill。** 以相同情境盲评角色表达、虚假的共同经历和缺少回执的完成承诺。分别观察 Skill 的发现、加载、实际使用、产物验收、漏触发、误触发和版本回滚。
- **成本与延迟。** 在相同任务、模型、网络和验收条件下，分开度量工具发现、连接冷启动、核权、实际处理及恢复耗时。整任务计入输入、缓存与输出 token、检索、辅助推理、重试和人工补救，并报告成本和 P50/P95 延迟。
- **常驻运行。** 记录设备、工作负载、24 小时观测覆盖、空闲模型调用、资源占用与中断后的恢复结果。分别计数调度器唤醒、出现待处理业务与实际调用模型。

### 13.2 让一次巡检和一次提醒都有来历

对跨天比价、日程观察和定时简报，先约定观察窗口、去重单位、有效条件、时区与通知期限。持续巡检需要四项计数：

| 观察项 | 计数依据 |
| --- | --- |
| **应巡检次数（Scheduled Checks）** | 按委托在该时段的有效版本计算应巡检的窗口数。暂停前后的窗口分别按当时生效的时间表归属。 |
| **实际有效观察次数（Effective Observations）** | 在应巡检窗口内取得授权且足以判断条件的有效资料。判断为“没有变化”也算有效观察。同一窗口重试成功只计一次，断网未取得资料的窗口记录漏检原因。 |
| **符合提醒条件次数（Trigger-Qualified Events）** | 按稳定事件标识记录满足业务条件的候选机会，例如一份信息完整、仍然有效且低于约定价格的报价。静默时段、上一次通知状态及再次打扰所需降幅在下一步判断。 |
| **实际送达次数（Delivered Notifications）** | 通知取得与原请求、接收目标相匹配的送达回执，按通知标识去重。只观察到服务受理时，记录到受理这一层。 |

窗口、事件、通知各有自己的计数单位。一次巡检可以发现数个机会，一条晨报也可以合并多个机会。判断漏提醒时，按事件关联通知及其回执，区分按委托抑制、合并送达、仍在允许期限内等待、等待对账、到期未送及已确认的失败。跨窗口迟到的回执回填原事件。处于 `UNKNOWN` 的发送按原标识继续核对。

同时报告就绪的独立节点中有多少无需用户催促即继续推进，多少次本应由用户拍板的决定得到了及时呈现。比较已批准 Skill 复用前后的协调开销时，同列产物验收质量、用户干预次数和整任务成本。[持续工作的验证场景](../parts/06-persistence-and-operations.md#part-6)

### 13.3 六类证据与发布门禁

每条结论绑定到具体能力、版本、环境和场景。以下标签记录已经取得的证据：

| 标签 | 能支持的结论 |
| --- | --- |
| `SOURCE_PRESENT` | 固定提交包含相应源码。 |
| `CONFIGURED` | 相应组件在指定环境中完成配置或接线。 |
| `CONTROLLED_PASS` | 受控测试、夹具或具名故障注入用例通过。 |
| `PROVIDER_PASS` | 指定版本在真实模型调用中通过所列场景的验收条件。 |
| `DEVICE_PASS` | 在指定实体设备上实测通过所列工作负载与用户操作。 |
| `PRODUCTION_PASS` | 在记录的生产环境、工作负载与观测期限内满足验收条件。 |

尚未运行的项目标 `NOT_RUN`，已有尝试但结果未能判明的项目标 `UNKNOWN`。模块集成、受限试用与日常发布各自声明所需证据，按受影响的路径逐项判断。有关安全与事实完整性的负向用例一旦发现越权读取、撤回或过期记忆再注入、虚报交付或重复不可逆效果，暂停对应能力的晋级，直到问题修复并在受影响路径完成复验。

失效恢复应覆盖重复派工或重复提交、修订与模型请求并发、旧回执晚到、Worker 结束后通知失败、Core 快照部分读取失败、请求装配后撤权、Skill 同名及 Persona 清单冲突、断网或磁盘满、Mac 窗口关闭、未确认外发及恢复后版本冲突。一般质量指标沿用已说明的基线与测试集，门槛由实际任务和工作环境确定。
