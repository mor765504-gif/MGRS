## 第十四条 · 渐进演化与最小侵入原则

### 14.1 先可观测，再改运行行为

Mimi Harness 复用 Hermes 的 Agent Loop、工具加载、会话压缩与基础委派能力。改造记忆排序、任务调度或恢复机制前，先从现有宿主、Core、原生会话及任务记录取得足以复验的基线。每项改动写清要改善哪一种用户工作、影响哪些组件与旧数据、怎样检查结果，并在已有的负责范围内实施。额外引入辅助模型、重排服务或执行阶段时，以同一批任务比较质量收益、时延和成本。

### 14.2 四个实施阶段与现有工作项

P0 至 P4 是工程路线中的工作项。下表按四个阶段组织它们，便于在每一阶段找到对应的运行契约和验收对象。

| 阶段 | 原工作项 | 改动与核验 |
| --- | --- | --- |
| **一、边界可观测** | **P0** | 读取当前可信身份、有效 Grant、Persona 来源、Skill 视图、MCP 权限、压缩设置与原生回执。分别标明尚缺实现、已有实现但未配置、已配置但未接通、以及待实测的路径。 |
| **二、受控上下文投影** | **P1** | 在 `mimi_memory` 的事实投影内落实权限过滤、可解释的确定性选择和首版 2000 字符预算。任务必需输入与 Persona 插槽分别从其权威来源取得。用真实中文样本、权限收窄和撤回用例核对最终请求。 |
| **三、交接、交互与语境** | **P2、P3** | **P2** 贯通原生输入及结果回执、授权接收者与具名验收，核对现有 Skill 发布服务（Skill P6）到原生加载器的路径。GenUI 按控件分别判断渲染、本地编辑和业务动作就绪。**P3** 保留现用 Persona 配置，比较语境适配、表达质量、相关性、延迟与缓存成本，有据可查地决定是否引入更复杂的表达选择。 |
| **四、持续运行与故障恢复** | **P4** | 在目标 Mac 或服务器上记录真实负载、24 小时观察时段和中断条件。核对持续委托的四项计数、独立节点推进、已接任务恢复、旧执行静默与未决外部效果。按具体场景记录通过项、失败项和仍缺的证据。 |

受影响的行为、验收证据和结果随版本记录。与产品边界有关的变更由独立审阅者核对影响范围，再决定可采用该版本的工作负载与运行环境。[可靠性度量与晋级门禁](13-reliability-and-promotion.md#mgrs-13) · [工程证据记录](16-capabilities-and-gaps.md#mgrs-16)
