## 1. 宗旨、边界与禁止事项

**MGRS（Mimi Governed Runtime Standard）是秘秘面向自主 Agent 与多 Agent 协作设计的专有治理协议。** 一个用户可以从日常会话交出任务，让后台助手在各自的工作空间处理资料，途中修改要求，稍后再回来收取结果。贯穿这些环节的是用户的授权、任务要求的版本，以及每次实际操作留下的依据。

**Agent 的自主性体现于选择方法；治理的约束体现于权限、事实、责任和效果。** 模型采用何种思考过程、怎样规划、使用何种模型架构，由实现选择。宿主通过可观察的行为与实际效果检查协作是否满足四个目标。

1. 每项任务、结果和外部操作都能追溯到授权主体和确定版本。
2. 每位执行者能在需要时取得相关上下文和技能，按权限回读原件。
3. 压缩上下文、更换会话、交接或宿主中断后，执行者能找回原任务，对账结果未知的操作，避免重复执行。
4. 普通聊天和小任务保持低开销。复杂协作和高风险操作采用与结果相称的约束和独立核验。

秘秘在既有宿主上实现这些要求。Hermes 负责原生 Agent Loop、MCP、Skill 与心跳，Core 维护可写事实。抽屉提供只读视图，Persona 装配本轮表达，工坊隔离并承接受管任务。秘秘自研搜索策略通过同一工具循环完成查询、原件阅读、追查和停止判断。每项事实只保留一个权威写入方，协议禁止再设全局调度器、Agent Loop、记忆写入权威或通用管理 Agent。[六个治理面](02-governance-planes.md#mgrs-2) · [搜索策略](../docs/006-search-strategy.md)

协议独立于特定模型或云厂商。任务准入不得由固定模型、角色或时间窗决定。一般请求按已有授权直接执行，多轮需求问答和独立模型复审均按任务需要启用。第三方工程流程插件不得自动安装。外部方法可供参考，权限和协议由秘秘实施。开发控制平面的责任分工、并发上限及运行代次只适用于开发工作；产品容量须按实际设备与工作负载度量。

个人单宿主和自有 VPS 是部署假设，约 2 核 4 GB 是架构体量目标。隐私网关脱敏、物理隔离、基于 TEE 的机密计算分别依靠不同机制实现保护。具体部署承诺需有对应实现与验证依据。产品对用户选择模型、工具和算力的考虑见[产品总览](../docs/MIMI-OVERVIEW.md)，设计来源见[决定 D07 至 D15](../docs/DECISIONS.md)。
