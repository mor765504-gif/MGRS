## 第十一条 · 状态延续、中断恢复与三项对账

### 11.1 中断不改变工作的逻辑身份

个人 Agent 的工作天然跨越时间、设备与运行环境变化。MGRS 要求：**客户端窗口关闭、网络短暂断开、切换推理模型或宿主进程重启，重新接续的仍是原任务（`task_id`）。宿主按当前有效授权与任务版本决定下一步，已发生的执行事实保留原归属。**

- **窗口关闭**：Mac 或 Web 前端关闭仅代表交互视图退出；后台受管任务是否继续运行由宿主配置决定。重开客户端时回读原有会话与任务状态。宿主休眠期间保留观察空档，唤醒后按当前条件重新检查。
- **网络中断**：连接恢复不等于重新授权，也不等于允许盲目重发；系统必须先核对断网前已发出操作的真实回执。
- **模型切换**：运行时从当前有效的 `Core` 事实、原生会话、任务版本与必要原件重新装配上下文，同时核对最新撤权与用户修订。

周期例程沿提供方与 `job_id` 查找委托，各次运行用 `run_id` 区分。领域观察沿自己的业务标识恢复，普通对话沿原生会话恢复。

### 11.2 恢复与运行中的三项独立判定依据

中断恢复中最危险的错误，是把“账本写入权”“旧执行器是否停稳”和“外部效果是否发生”混为一谈，导致重复发信或提前释放独占资源。MGRS 规定这三项决定必须分别依据三类硬证据作出：

1. **`writer epoch` 决定谁能写任务账本**
   - 单宿主同一时刻只允许唯一持有 `active writer` 租约与最新单调递增 `epoch` 的实例写入任务账本。
   - 新实例在取得写入权时，由权威存储原子地推进 `epoch`。存储层拒绝旧代次的写入，新写入者仍可按原尝试核对迟到回执。
2. **`quiet` 证据决定何时能释放旧尝试占用的独占资源**
   - 独占工作目录、文件锁、浏览器会话或受限执行槽位必须绑定具体 `attempt_id`。
   - 执行器的停止回执，或宿主对原进程组、容器及其所占资源的核查，可以证明该尝试对相应资源已经静默。仅有取消请求、租约到期或账本 `epoch` 换代时，继续保留相应独占预约；资源层可以隔离新的写入目标，让无争用的工作继续推进。
3. **远端回执决定外部操作如何对账**
   - 对于非幂等外部操作，已取得受理标识的记录为已受理，取得最终效果的证据后登记相应结果。超时或断线使结果无法判明时，保留 `UNKNOWN`。
   - 对账时必须沿用原 `Attempt` 的 `request_key`、`effect_id` 或原生操作标识核查结果，严禁更换新 ID 盲目重试；服务未提供按请求键反查的接口时，可在授权范围内核对订单、消息或目标对象的版本记录。仍无法判定时保留 `UNKNOWN`，将具体待核对象交给有权核验的人，并继续无依赖且无资源冲突的工作。

### 11.3 启停顺序与数据变更连续性

- **先核权、再对账、后推进**：宿主重启后的标准恢复顺序为：验证可信身份与当前授权代次 → 取得新 `epoch` 并恢复原生会话与 `task_id` 合同 → 分别核查旧 `Attempt` 的静默证据与未决效果 → 按最新有效版本重建上下文并继续推进。健康检查接口返回成功仅证明端口存活，不代表模型、工具或外部账号已就绪。
- **备份、升级与回滚边界**：核心数据库快照恢复成功不等于外部执行器与未决发送已恢复；软件版本升级必须声明状态迁移路径，而版本回滚严禁删除升级期间已经形成的真实外部回执、任务修订或用户撤权记录。

跨宿主迁移时，原宿主先交回相应的写入权与外部执行资格，或由对双方均有效的栅栏阻断旧方。目标端核对移交记录、持久工作环境、凭据、授权与未决操作后取得写入代次。仅在目标机器上修改数据库里的 `epoch` 无法约束仍在线的原机器。回滚后同样要核对最新撤权与原操作回执。

`ProductRuntime` 负责组件启停和有序排空。运行循环由任务就绪、原生回执、时间条件或用户输入唤醒。模型在需要新判断时介入。磁盘或持久化故障使接单无法入账时，宿主报告受阻。运行质量与持续时长按 [第十三条](13-reliability-and-promotion.md#mgrs-13) 的实际工作负载验证。
