## 第八条 · 经验沉淀与 Skill 生命周期

### 8.1 从一次性经验到受控可复用能力

个人 Agent 的长期价值之一，在于把解决某类问题的有效做法沉淀为可复用的 `Skill`，从而在后续同类任务中减少试错与人工协调成本。任务历史提供工具组合、执行回执、产物验收与适用条件。反复奏效的做法可据此形成经验候选，再按发布流程验证和批准。[持续实践与可复用的工作方法](../parts/06-persistence-and-operations.md#part-6)

MGRS 为 Skill 确立清晰的生命周期治理语义，确保方法复用安全可控：

`DISCOVERED（发现方法来源） → CANDIDATE（形成候选） → TESTED（离线与边界测试） → STAGED（待审预发布） → APPROVED（批准入库） → ACTIVE（按域生效）`

当某个 Skill 出现版本过期、依赖失效或越权异常时，系统可将其置入 `DISABLED`（停用）、`QUARANTINED`（隔离排查）或 `REVOKED`（吊销），并支持按版本回滚。受管发布沿用 Skill P6 的保存、预发布、批准、执行与恢复记录，同一 Skill 目录由一个发布方写入。

### 8.2 Skill 包的治理契约

每一项进入受管分发的 Skill 都必须声明清晰的边界契约。

- **来源与版本**：标准名称、固定版本、来源与原许可、变更记录和可回滚版本；
- **适用边界**：明确的入口触发场景、适用前提与明确的**非目标（不适用范围）**；
- **能力与输入输出声明**：所需前置条件、依赖的外部能力清单、预期输出结构、失败或拒绝条件，以及至少一组正反验证样例；
- **方法说明与执行权限分离**：纯文本方法指南（`SKILL.md`）仅向模型提供工作思路与步骤规范；若 Skill 包含可执行脚本或调用高风险工具，必须单独声明所需能力并在每次执行时接受第七条的 `E0–E3` 权限门禁检查。

受管方法覆盖探索与设计、表达与编辑、审核与交付三类用途。探索型 Skill 可协助比较可行方案，编辑型 Skill 保留作者原意和来源，审核型 Skill 检查合同、产物与例外。各自使用同一套发布和权限规则。

### 8.3 复用加载与持续任务中的重检纪律

- **按需加载**：模型通过目录感知已批准的 Skill 摘要，仅在判断适用时按需读取完整正文，避免无谓占用上下文预算。通过当前 Profile 的只读视图接入 Hermes 原生目录与加载器，分别记录目录可见、正文加载、脚本或工具实际调用，以及产物验收。
- **跨恢复重检**：当持续任务在宿主重启、模型切换或跨天调度中复用既有 Skill 时，运行时必须重新核验当前 `Profile`、Skill 批准状态、来源版本及对应授权仍然有效，严禁沿用恢复前缓存的未校验执行许可。
