# MGRS 还想和大家一起讨论什么

[框架草案](../MGRS.md) · [已经形成的设计决定](DECISIONS.md) · [参与讨论](../CONTRIBUTING.md)

我最想听的一类意见，是「你这个想法放到我这里，就得改一改」。比如同一句「按以前那样处理」，私人助手也许已经很懂你了，可换成团队共用的助手，到底该按谁的习惯？下面这些地方，0.1 还留着讨论空间。

## 哪些事可以放心交给助手？

<a id="q01"></a>

**Q01 · 做法和目标的界线。** 你让助手做一份有原文出处的比较。它可以换个地方找资料，但如果原件没找到，只能先交一份线索，这已经改变了你能拿结果做什么。哪些调整它可以自己决定，哪些得回来跟你商量？

<a id="q02"></a>

**Q02 · 小事值得用多少工夫。** 查明早几点开会，能直接回答就好。几个人一起准备对外发言，可能值得分工、留记录，再请人看一眼。中间的任务怎么选？

<a id="q05"></a>

**Q05 · 接手的人凭什么采信上家的结论。** 一张报价表可以对原件，一句「对方愿意接这个任务」往往还得听听当事人的意思。什么时候看材料就够，什么时候需要另一个人的判断？

<a id="q11"></a>

**Q11 · 什么算合作得好。** 哪些要求你希望每个助手都守住，哪些只要用起来有改善就好？大家可以拿自己在意的任务，提出愿意据以判断的条件。

## 助手熟悉你到什么程度合适？

<a id="q07"></a>

**Q07 · 跨场合共享的记忆。** 你愿意让个人助手和项目里的助手都知道你偏爱先看结论吗？谁可以改这个偏好？它们又有哪些资料应该各自保管？

<a id="q08"></a>

**Q08 · 人格和主见。** 一个会开玩笑、也会提出不同意见的助手，怎么在闲聊、工作和你认真纠正它时都像同一个角色？哪些反应让你觉得它真的理解了谈话背景？

<a id="q03"></a>

**Q03 · 谁来安排这一次该看什么。** 记忆、角色、任务都有各自的来处。到实际接手时，由谁把它们放到一起，解决内容重叠或相互冲突的问题？

<a id="q04"></a>

**Q04 · 实在放不下时怎么选。** 原文、做事方法和你刚补的要求都可能很长。哪些可以先放回抽屉，需要时再读？哪些话一旦省掉，就会把事情做偏？

## 做熟的事情怎样留下来？

<a id="q06"></a>

**Q06 · 学会一种做法以后。** 助手可以从反复做过的事里整理出方法。留一份写作提示，和安装一个能操作文件的脚本，分别该由谁决定什么时候能用？

<a id="q09"></a>

**Q09 · 合上电脑以后。** 你关了窗口、机器休眠或断了网，希望已经交代的哪些事继续，哪些事等你回来再接上？

<a id="q10"></a>

**Q10 · 哪一处说了算。** 两个入口都能改同一份日程，或者有两处都能发出同一条通知，应该让谁负责保存决定、谁负责把它送出去？

<a id="q12"></a>

**Q12 · 哪些材料适合拿出来共创。** 项目可以公开讨论。为了让其他人能提出有根据的意见，还可以提供哪些脱敏例子、源码或测试材料？许可和再分发条件也需要项目所有者进一步确定。[现有定位](../NOTICE.md)

挑一个你有切身体会的问题就好。说说事情是怎么发生的，助手当时怎么做，你更希望它怎么做。[到仓库讨论](https://github.com/mor765504-gif/MGRS/issues)
