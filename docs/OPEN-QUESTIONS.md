# MGRS 还想和大家一起讨论什么

[框架草案](../MGRS.md) · [已经形成的设计决定](DECISIONS.md) · [参与讨论](../CONTRIBUTING.md)

比如我跟自己的助手说「按以前那样处理」，它可能真知道我什么意思。可要是团队里三个人都这么说，又刚好各有各的习惯，它该听谁的？写 0.1 的时候，有些地方换一个用法，我自己也会拿不准。

<a id="哪些事可以放心交给助手"></a>

## 把一件事交给助手

<a id="q01"></a>

**Q01 · 做法和目标。** 我想要一份能对着原文看的比较，去哪找原文，可以让助手自己选。实在找不到，先给我几条线索也有用，可我拿着这些还写不了原来的稿子。这一步是不是该回来找我商量？我想知道大家平时把决定权交到哪里。

<a id="q02"></a>

**Q02 · 一件小事花多少工夫。** 我早上只想知道今天几点有会，翻一下日历告诉我就好。要准备几个人一起对外讲的话，我倒是愿意多花点时间，让他们各自找材料，留份记录，再请人读一遍。夹在中间的那些事，什么情况下也值得这么做？

<a id="q05"></a>

**Q05 · 接过来的东西能信到哪一步。** 报价单上的数不确定，我可以翻原件。可一个助手告诉另一个助手「对方愿意接这个任务」，就算找到了那段会上的原话，说话的人也可能只是客气了一下。遇上这种情况，有人愿意让助手自己判断，也有人要找当事人再问一句。

<a id="q11"></a>

**Q11 · 我怎么知道它们合作得好。** 比如几个助手分头给我理邮件，我会在意最后少花了多少时间，也会在意有没有哪封被漏掉。前者快一点当然好，后者在一些任务里，一封都丢不得。我想听听你会拿哪件事来判断，哪些要求得每次都守住，哪几样只是做得好些更省心。

<a id="助手熟悉你到什么程度合适"></a>

## 助手跟一个人用久了以后

<a id="q07"></a>

**Q07 · 我的习惯能带到哪里。** 我喜欢先看结论，可能很愿意让私人助手和项目里的助手都记住。可组员有一天说「这篇先把过程讲完」，我大概还是想让它只改这篇。哪个助手可以改长期偏好，哪些事留在这个项目里就好？

<a id="q08"></a>

**Q08 · 助手的性格。** 我可以喜欢一个平时会开玩笑、对我的想法也有点自己意见的助手。等我认真纠正它，要是它还只顾着跟我接梗，我大概就没耐心了。你用久了，什么时候觉得它还是你熟悉的那个助手，而且这次也真听懂了？

<a id="q03"></a>

**Q03 · 这回该给助手看什么。** 之前记住的偏好、秘秘平时跟我说话的习惯、我对这次任务的交代，都有可能提到同一件事，写法还不一样。最后由谁来挑、给各部分留多少位置？如果前面两处都写着我以前的习惯，这回我刚刚改了主意，也得有人把这个意思理顺。

<a id="q04"></a>

**Q04 · 一次看不下那么多怎么办。** 一份原文已经很长了，再加上做事的方法和我刚补的要求，助手一次可能读不下。有些材料可以等它用到了再回来翻。要是我特地说过有一页暂时别往外发，这句话放到哪一步都得算数。我想讨论的是，什么可以晚一点再读，实在装不下的事又该怎么接着做。

<a id="做熟的事情怎样留下来"></a>

## 再用一次，或者换个地方接着用

<a id="q06"></a>

**Q06 · 用顺手的做法能不能留下。** 同一种汇报写过几次，助手替我整理一份写作提示，我可能马上就愿意再用。要是它整理出来的是个会读写文件的脚本，我多半想先看看它会动到哪里。用户自己装的办法和助手总结出来的办法，分别由谁决定可以用了？

<a id="q09"></a>

**Q09 · 合上电脑以后。** 有时候我只是关掉聊天窗口，有时候机器真的睡了，也可能断了网，甚至得重启。之前交代的事，哪些我会以为它还在做？哪些我宁愿等回来以后看一眼，再让它接着做？

<a id="q10"></a>

**Q10 · 别让两个地方各做一遍。** 如果手机和电脑都能改我同一份日程，我当然希望两边都看得见新时间。可要是两边还各自给同事发一次改期通知，人家大概要问我是不是又改了。到底由哪一处记下这次决定，哪一处负责把通知发出去？

<a id="q12"></a>

**Q12 · 还有哪些材料值得公开。** 这份框架的文本已经按 CC BY 4.0 授权。如果你想判断里面的某个做法，光读草案可能还不够。你更想看一段去掉私人信息的实际例子，还是相关的源码或测试？哪些补充材料可以拿出来、能怎么用，还要看材料本身。[许可与使用范围](../NOTICE.md)

有哪一条刚好说到你碰过的事，直接把那件事讲出来就好。你也可以说，换成我，根本不会让助手这样做。[到仓库讨论](https://github.com/mor765504-gif/MGRS/issues)
