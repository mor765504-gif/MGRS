本页记录原稿成文后、本次对话中能够确定的设计决定。它不是逐字聊天转录，也不包含无关个人资料。这里不补造时间戳、不把助手建议写成用户批准。

## D01 · 协议而非独立运行中间层

**状态：用户明确确认。**

用户原话：“肯定是协议啊 我就得拿来好好的和大家聊一下我这套治理协议到底情况是怎么样的”。

归档含义：MGRS 是约束秘秘组件协作的协议，不新增一个独立 Agent 框架或调度中间层。协议正文、秘秘实现与验证材料可以分别讨论。

## D02 · 秘秘内部专有标准，允许外部讨论与审查

**状态：对话已选定的定位。**

用户选择“主要用于秘秘内部，但允许其他开发者参与讨论和审查的专有标准”；随后对话沿此定位继续。

归档含义：首先服务秘秘，不因外部可讨论而自动变成行业通用协议或开源软件。可公开的规范段落、许可条款及邀请名单仍应另行确定。仓库本身现已公开为 `mor765504-gif/MGRS`。

## D03 · 不使用 Superpowers 作为治理依赖

**状态：用户明确要求。**

用户原话：“别用superpower 我都完整的设计一套全新可靠的治理标准来”。

归档含义：不安装或依赖该工作流框架，不用它来规定秘秘的控制权和任务纪律。保留已有 Core、Hermes 和工坊成果，治理合同由秘秘自身定义。

## D04 · C0 判断与验收事实的边界

**状态：此前对话按认可处理；完整授权边界尚未逐条定稿。**

此前讨论提出：C0 保留规划、协调、判断和修复建议权，但不凭判断改写真实回执或绕过已经确定的验收条件。用户回复“对的”，助手据此沿这一方向继续。

这份认可不能扩展为 C0 已被授权任意修改验收规则、删除失败记录或降低交付目标。规范中对应讨论主要见第 5、6、15 章。

## D07 · 产品形态是个人 Agent（PA），不是更聪明的聊天机器人

**状态：UP 在 B 站公开回复中明确宣布（2026-11-07）。**

来源：[BV1vix26sEzR](https://www.bilibili.com/video/BV1vix26sEzR/) 置顶通俗解释。

归档含义：秘秘面向长期陪伴式办事——查资料、操作软件、整理文档、多 AI 分工；中途可改主意而不必重开；应记住习惯与既往，而非每轮从零解释。MGRS 服务的是这类长期会话与可分工协作的可靠性，而不是单次问答评分。

## D08 · 多 Agent 主问题已从「如何协作」转向「如何治理协作」

**状态：UP 公开宣布（2026-11-08）。**

原话要点：多 Agent 能力本质是 harness 调度与工程治理；工程长尾与假验收专门优化；协作高低看准确率、延迟、用量/成本与任务可靠性。

归档含义：MGRS 把治理合同、证据分层、假验收拒绝与可靠性度量放在中心。不得把「能开多个 Agent」写成已满足治理标准。

## D09 · 秘秘不是 SaaS；与大厂生态是互补，不是入口绑死

**状态：UP 公开宣布（2026-11-08）。**

原话要点：通过 MCP 与 GUI 使用大厂生态是「帮你操作」而非绑定；目标是生态自由、数据自由、成本控制与多 Agent 协作体验；竞争叙事是伪命题。

归档含义：协议不把单一云厂商或模型供应商写成运行前提；授权与事实权威仍在可信宿主与用户控制面。

## D10 · Hermes 为底座；记忆 / Persona / 工坊治理是差异化重点

**状态：UP 公开宣布（2026-11-07）。**

原话要点：内核用 Hermes；复用其 MCP、Skill、心跳；其上下文管理偏保守，记忆与 Persona 需加强。每轮冷启动用「抽屉」分层压缩；工坊承担多 Agent 协作治理与按任务类型的单窗口隔离，与单入口共享基本记忆但不全部继承。

归档含义：与正文第 2、4、8、9 章及「不另建第二套 Agent Loop」一致。公开表述中的「四层抽屉」是产品说明；规范仍以只读投影 / 权威分治为准，避免把抽屉写成第二套可写账本。

## D11 · 搜索与信息质量策略属于治理输入

**状态：UP 公开宣布（2026-11-07）。**

原话要点：在 Hermes/Exa 基础上优化；英文源优先于中文；专业问题 OpenAlex 等优先于 Wiki；降低低置信度糊弄。

归档含义：方法抽屉与 Skill/工具选择应能表达信息源优先级；具体排序表属于产品配置，可不写入协议硬条款，但验收不得把低置信度拼凑标成已核验事实（呼应 G06/G13）。

## D12 · 隐私：零访问加密计算为目标；信任是渐进态；鼓励自有 VPS

**状态：UP 公开宣布（2026-11-07〜08）。**

原话要点：算力提供方在调用模型时无法访问用户数据（零访问 / TEE 方向）；前期可用隐私网关做占位符级脱敏；物理隔绝与密码学是不同方向而非单纯高低层级；只要上网就有理论泄露可能；鼓励自有 VPS 做隐私管理；信任托管是漫长中间态，不是有/无二元。

归档含义：MGRS 记录为产品安全目标与部署哲学，**不**把 TEE/机密计算标成已验收能力。宿主与 Profile 隔离、授权与撤回仍是协议可强制部分；加密推理属于待证实施路径。

## D13 · 治理框架文档可先于完整产品开源，供讨论审查

**状态：UP 公开宣布（2026-11-07）；仓库现况已公开。**

原话要点：治理框架文档可能比产品更早开源讨论；涵盖 Skill/MCP、memory/persona、搜索、宿主、交互、上下文、多 Agent 分级治理、CLI/GUI 网关、个人 VM、浏览器选型，以及架构体量目标（约 2C4G VPS）。

归档含义：公开 `MGRS` 仓服务于讨论与审查；文档公开 ≠ 产品符合性完成，也不自动授予实施或合并权（见 CONTRIBUTING）。

## D14 · 支付与合规边界（产品声明，非协议运行时条款）

**状态：UP 公开宣布（2026-11-08）。**

原话要点：GUI 操作、用户接管支付；实体在香港；不碰支付牌照；秘秘不是 SaaS；两地隔离版本。

## D15 · 单宿主长运行与低成本部署目标

**状态：UP 公开宣布（2026-11-07）。**

归档含义：与第 11、13、14 章单宿主恢复及 P4 真实验收一致。体量数字是目标，不是已测通过的容量证明。
