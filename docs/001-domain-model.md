# 001 · 换个窗口，怎么算还在做同一件事？

[首页](../README.md) · [导读目录](README.md)

今天你给秘秘三份场地报价，让它算一张活动预算。明天换个窗口，你补一句“把布置费也算上”。这句话很短，其实你默认了不少事情。它得知道你指的是昨天那场活动，场租已经算过，三份报价还找得到。要是每次补一句话都得先把事情重讲一遍，那长期助手用起来也挺累的。

所以我想把**任务**放在协作的中心。你可以换个窗口说话，秘秘也可以换一个 Agent 接手。只要还在办这场活动，大家就该能找到同一项预算，知道你最初要什么，后面又改了什么。

## 改一句要求，之前的工作还算数吗？

场租当然可以接着用。变化的是总价，还有按总价排出来的先后顺序。假如其中一家压根没提布置费，表格里留一句“这家还要问”，比替它填个零有用。接手的人知道缺的是哪句话，也知道该回到哪份报价去问。

这就是为什么我会把**要求、材料和结果**分开。要求跟着你现在想办的事走，材料留着原来的人是怎么说的，结果则对应当时那版要求。你改主意后，秘秘就能有选择地重做受影响的部分。[任务与交接](../MGRS.md#collaboration)

还有个容易被忽略的细节。你既用秘秘处理自己的事，也用它帮社团做预算。负责算这张表的助手可以读你给社团的报价，可你个人账户里还有什么，跟这场活动没有关系。让同一个人能接着做事、又给不同的工作留出各自的范围，这两点我都想保留。[身份与资料范围](../MGRS.md#extensions)

一个值得讨论的情况是，有一家始终没回复布置费。秘秘可以先把已知费用算出来，也可以分别估几种情形供你选。如果你原先要的是能直接据此订场地的一口价，这几种情形能帮你走到哪一步？这种差别会影响助手什么时候可以自己换个做法，什么时候应该回来找你。它也是[待讨论的任务边界](OPEN-QUESTIONS.md#q01)里很实际的一题。
