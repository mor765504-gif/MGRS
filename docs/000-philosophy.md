# 000 · 我为什么想聊 Agent 治理

[首页](../README.md) · [秘秘的产品哲学](MIMI-OVERVIEW.md) · [框架正文](../MGRS.md)

评论区有个朋友问我，别的产品也能让几个 Agent 互相交流，从视频里怎么能看出来秘秘的协作更好？光看它们一人说了几句话，确实挺难看出来的。我当时讲「如何治理协作」，想说的是分了工以后碰到的事。[当时的讨论](sources/2026-11-09-bilibili-bv1vix26sEzR.md)

比如请秘秘整理一场会，找谁查资料、让谁核出处，这些它可以自己安排。等我看到第一稿，才想起来里面有一段只适合我们几个人私下谈，就跟它说「那段先拿掉，纪要只发给今天在场的四个人」。我在主窗口说了，写稿的还在写原来那段，负责发的手上也还是原来那份名单，那我岂不是还要去两个窗口各讲一遍？

我希望平时只要跟秘秘说这一遍就够了。后面到底是两个 Agent 在干活还是三个，我可以不用管，但最后发给谁，我改了主意，它们就都得知道。[协作者之间怎么交接](004-execution-and-evidence.md)

## 熟悉一个人，也得懂得分寸

我希望秘秘用久了能懂我一点。比如我习惯把待办放在纪要最后，它记得这个就挺好，省得我每次都讲一遍。可要是散会以后，我私下跟它吐槽了一句「这会发封邮件不就好了」，结果准备给同事发纪要，一打开，怎么这句也在里面？

下回我多半还是会用秘秘。纪要我自己写好了，让它帮我改改措辞，这个我放心。可有些事我自己都还没想明白，本来挺想跟它聊两句的。想想上回那份纪要，还是算了，我自己再想想。[我在评论区聊过这个问题](MIMI-OVERVIEW.md#trust)

所以做记忆的时候，我蛮在意秘秘什么时候会想起一件事。比如它临时找个 Agent 来帮我核引文，给它看那几页原文就够了。要是换个项目，我以前交代过的习惯，哪些还希望它照着做？这个我也想听听大家平时怎么处理。[上下文与记忆](003-context-and-memory.md)

## 什么时候问一句，会让人觉得刚好？

我早上只想知道几点有会，秘秘看一眼日历就能告诉我。要是它还让我确认一遍该怎么查，那我做这个助手图什么呢？可要替我把会议改到另一天，另外三个人也得跟着改安排。这时候先让我看一眼，它倒是替我省了事。

也有人可能觉得，组里每周都这么排，连挪会也可以放心让助手去做。我想把 MGRS 拿出来讨论，就是因为我自己用着顺手的安排，换个团队未必还顺手。你平时有哪件事已经放心交给助手了？怎么用到这一步的？[哪些判断可以交给助手](005-review-and-conformance.md)
