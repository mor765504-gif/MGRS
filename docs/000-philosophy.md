# 000 · 我为什么想聊 Agent 治理

[首页](../README.md) · [秘秘的产品哲学](MIMI-OVERVIEW.md) · [框架正文](../MGRS.md)

之前有朋友问我，现在好几个产品都能让一群 Agent 分头干活，也会互相交流，那秘秘到底在做什么？我当时说，我越来越关心的是怎么治理协作。这个词听起来有点大，放到日常工作里，起点其实很朴素。你把事情交给一个助手，总不能到最后，还得自己去当另外几个助手之间的传话人。[当时的讨论](sources/2026-11-09-bilibili-bv1vix26sEzR.md)

比如我把一份会议纪要交给秘秘，里面哪几句话要回头找材料，哪些待办要单独列出来，它可以自己安排。它想找另一个 Agent 帮忙核出处，也可以。可我看了第一稿才意识到，有一段只适合我们几个人私下讨论，于是补了一句「那段先拿掉，只发给今天在场的四个人」。我只想说一遍。之后谁改稿、谁负责发，这句话都应该算数。

这就是我愿意给 Agent 的自由。怎么把纪要写好，它有自己的判断。写给谁、哪些内容我愿意分享，我可以在任何时候改主意。分工要能替我省掉中间的协调，同时给我留下随时插一句话、改变事情走向的地方。[协作者之间怎么交接](004-execution-and-evidence.md)

## 熟悉一个人，也得懂得分寸

我希望秘秘用久了能懂我一点。比如我习惯把待办放在纪要最后，它记得这个就挺好，省得我每次都讲一遍。可要是散会以后，我私下跟它吐槽了一句「这会发封邮件不就好了」，结果准备给同事发纪要，一打开，怎么这句也在里面？

下回我多半还是会用秘秘。纪要我自己写好了，让它帮我改改措辞，这个我放心。可有些事我自己都还没想明白，本来挺想跟它聊两句的。想想上回那份纪要，还是算了，我自己再想想。[我在评论区聊过这个问题](MIMI-OVERVIEW.md#trust)

所以做记忆的时候，我蛮在意秘秘什么时候会想起一件事。比如它临时找个 Agent 来帮我核引文，给它看那几页原文就够了。要是换个项目，我以前交代过的习惯，哪些还希望它照着做？这个我也想听听大家平时怎么处理。[上下文与记忆](003-context-and-memory.md)

## 什么时候问一句，会让人觉得刚好？

我早上只想知道几点有会，秘秘看一眼日历就能告诉我。要是它还让我确认一遍该怎么查，那我做这个助手图什么呢？可要替我把会议改到另一天，另外三个人也得跟着改安排。这时候先让我看一眼，它倒是替我省了事。

同样觉得「助手应该主动」的人，对这两件事也可能有很不一样的判断。我想把目前的想法写出来，让做 Agent 的人和每天用 Agent 的人可以对着同一个例子聊。你愿意长期交出去的一个决定是什么？即使助手再熟悉你，哪一步你还是想亲自来？[哪些判断可以交给助手](005-review-and-conformance.md)
